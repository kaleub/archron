Been revisiting the two-layer token approach again. Primitives, then semantic aliases on top. The pattern holds up across every platform I've used it on — Shopify, Webflow, now this.

## The core idea

Primitives hold raw values. Semantic tokens point at primitives and are the only thing components actually consume.

```css
:root {
  --color-blue-500: #2563eb;
  --color-action-default: var(--color-blue-500);
}
```

A rebrand only ever touches the semantic layer — components never change.

### Where it breaks down

1. When primitives and semantic aliases live in different cascade scopes
2. When someone references a primitive directly "just this once"
3. When the naming convention isn't enforced anywhere but memory

Comparison of approaches I've used:

| Approach | Migration cost | Learning curve |
|---|---|---|
| Hardcoded values | High | None |
| SCSS variables | Medium | Low |
| CSS custom properties (two-layer) | Low | Medium |

Nested example of what *not* to do:

- `.card`
  - `.card__body`
    - `.card__body__text` ← elements nesting elements, avoid this
  - `.card--featured`

Still the same conclusion every time: `var()` aliasing is what makes any of this migratable at all.
